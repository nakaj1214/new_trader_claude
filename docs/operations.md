# 運用メモ（確認方法とトラブル対応）

## 自動実行のスケジュール

| workflow | 時刻（日本時間） | 内容 |
|---|---|---|
| 毎日の売買判断 | 平日 17:30 | その日の終値で判断し、必要なときだけ Discord に通知。結果を `state/` に保存 |
| 〃（再試行） | 平日 19:30 | 17:30 にデータが揃っていなかった場合の再実行（処理済みなら何もしない） |
| 〃（最終確認） | 平日 7:30 | 前営業日が未処理なら処理する。それでもデータが無ければエラー通知 |
| バックテスト | 手動 | 過去データで検証し `reports/backtest_latest.md` を更新 |
| テスト | push 時 | プログラムの自動テスト |

- GitHub の予約実行は混雑すると数分〜数十分遅れることがあります。
- 同じ日を2回処理しないようになっています（`state/portfolio.json` の `last_session`）。
- 通知が届いたあとに保存（commit）が失敗した場合、次の実行で同じ通知がもう一度届くことがあります。内容は同じなので、注文は1回だけ出してください。

## 動作確認（保存も通知もしない）

Actions →「毎日の売買判断」→ Run workflow で **dry_run** にチェックを入れて実行すると、今日の判断で送るはずの通知文がログに表示されます。記録（`state/`）は変わりません。

## 通知の種類

| 通知 | いつ |
|---|---|
| 📝 注文してください | 売買が必要な日 |
| ✅ 約定したとみなした取引 | 注文の翌営業日 |
| 🗓 月次レポート | 毎月の最終営業日（入れ替え判断の日） |
| 📊 保有状況 | 毎週の最終営業日と、売買があった日 |
| ⚠️ / 📌 | データ欠損・株式分割・休止などのお知らせ |
| ❌ エラー | 自動実行が失敗したとき（その日の売買指示は出ていません） |

## よくあるトラブル

- **何も通知が来ない**: 売買が無い日は通知しません。毎週金曜（週の最終営業日）に「保有状況」が来ていれば正常です。来ない場合は Actions タブで「毎日の売買判断」の結果を確認し、`DISCORD_WEBHOOK_URL` が登録されているか見てください。
- **「株価データがまだ揃っていません」**: データ提供元（Yahoo Finance）の遅れです。翌朝の最終確認で自動的に再試行されます。
- **「前回の実行から日数が空きすぎています」**: GitHub Actions が長期間止まっていた場合に、実際の売買とのずれを防ぐため停止します。保有している株をアプリで確認し、`state/portfolio.json` を別名に移す（＝新しく始める）か、開発者に相談してください。
- **「前日から3割以上下がりました」**: 株式分割の記録が遅れている可能性があるため1日だけ判断を止めます。翌日も同じなら本当の値下がりとして扱い、ルールどおり売却指示が出ます。
- **注文し忘れた / 違う株数で買った**: システムは通知どおりに約定したものとして計算を続けます。次の月末の入れ替えで、システムの保有とあなたの保有を見比べて合わせてください（迷ったら、システムの保有に合わせるのが簡単です）。

## 設定を変えるとき

- `config/settings.yaml` を GitHub 上で編集して commit すると、次の実行から反映されます。
- 不正な値（例: `mode: real`）を書くとエラー通知が来て、その日は何もしません。
- 入金額を変える場合は `satellite.monthly_contribution` と `core.monthly_amount` を変更します。

## ブランチについて

- GitHub の予約実行は **デフォルトブランチ** でだけ動きます。最初に push されたブランチがデフォルトになっているので、`main` に名前を変えたい場合は Settings → General → Default branch から変更してください（そのまま使っても動作します）。

## 記録をリセットしたいとき

- `state/portfolio.json` を GitHub 上で削除（または別名に変更）すると、次の実行で設定の開始額から新しく始まります。
